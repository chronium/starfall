Apply authoritative click-to-move movement inside the exact Draft 0 graybox using Box3D-native single-precision spatial state in metres.

Acceptance criteria:
- Consume validated finite ground-point movement intent and advance Box3D-native position, velocity and collision state on fixed simulation ticks.
- Convert Starfall authoring metre components one-to-one into Box3D-native types without changing unit or precision and without maintaining a parallel fixed-point coordinate model.
- Preserve reproducibility through a pinned Box3D version and compatible build settings, stable body/shape creation order, stable entity IDs, deterministic application ordering and explicit sorting where query ordering is not guaranteed.
- Respect the zone's exact collision/navigation inputs and protected-town boundary contracts.
- Provide bounded ground-plane movement usable by player and monster rules without adding altitude or flight navigation.
- Keep client camera, pointer mapping, smoothing and animation presentational; client prediction may use the same simulation but must reconcile authoritative snapshots.
- Before activation, represent the approved coordinator-owned Box3D acquisition/integration prerequisite as a canonical dependency.
- Do not build a generic controller, navigation framework, terrain engine, pathfinding platform or fixed-point spatial model.
